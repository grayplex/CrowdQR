<objective>
Add missing database indexes for foreign keys, composite query patterns, and hot paths. Create an EF Core migration to apply the indexes.

Purpose: PostgreSQL does NOT auto-index foreign keys (unlike primary keys). Missing FK indexes cause full table scans on JOINs, which get worse linearly with data growth. Adding proper indexes is the single highest-impact database optimization.

Output: Updated CrowdQRContext.cs with comprehensive index definitions and a new EF Core migration.
</objective>

  <name>Task 1: Add missing indexes to CrowdQRContext OnModelCreating</name>
  <files>src/CrowdQR.API/Data/CrowdQRContext.cs</files>
  <action>
    Audit existing indexes in CrowdQRContext.cs and add missing ones.

    **Currently defined indexes:**
    - User: `Username` (unique) - EXISTS
    - Event: `Slug` (unique) - EXISTS
    - Request: `EventId` (single) - EXISTS
    - Request: `Status` (single) - EXISTS
    - Vote: `(UserId, RequestId)` unique composite - EXISTS
    - Session: `UserId` (single) - EXISTS
    - Session: `(EventId, UserId)` unique composite - EXISTS

    **Missing indexes to add:**

    1. **Event.DjUserId** - Foreign key used in `WHERE e.DjUserId == djUserId` queries (EventController.GetEventsByDJ, DashboardController.GetDJEventStats, ReportsController):
       ```csharp
       entity.HasIndex(e => e.DjUserId)
             .HasDatabaseName("IX_Event_DjUserId");
       ```

    2. **Request.UserId** - Foreign key used in joins (ReportsController unique participants):
       ```csharp
       entity.HasIndex(e => e.UserId)
             .HasDatabaseName("IX_Request_UserId");
       ```

    3. **Request (EventId, Status)** - Composite for the most common query pattern (DashboardController filters by EventId + Status):
       ```csharp
       entity.HasIndex(e => new { e.EventId, e.Status })
             .HasDatabaseName("IX_Request_EventId_Status");
       ```
       NOTE: The single `EventId` index already exists, and this composite index can serve queries that filter by EventId alone (leftmost prefix), so consider removing the standalone `EventId` index to reduce write overhead. However, it's safer to keep both during this phase and evaluate in Phase 4 with actual query analysis.

    4. **Vote.RequestId** - Foreign key used in `WHERE v.RequestId == requestId` and join queries (VoteController.GetVotesByRequest, COUNT subqueries):
       ```csharp
       entity.HasIndex(e => e.RequestId)
             .HasDatabaseName("IX_Vote_RequestId");
       ```

    5. **Vote.UserId** - Foreign key for the Vote -> User relationship:
       ```csharp
       entity.HasIndex(e => e.UserId)
             .HasDatabaseName("IX_Vote_UserId");
       ```
       NOTE: The unique composite `(UserId, RequestId)` already covers queries filtering by UserId first, but a standalone UserId index helps when querying votes by user without request context.

    6. **Session.EventId** - Foreign key used in `WHERE s.EventId == eventId` queries (SessionController.GetSessionsByEvent, DashboardController active sessions):
       ```csharp
       entity.HasIndex(e => e.EventId)
             .HasDatabaseName("IX_Session_EventId");
       ```

    **Summary of changes to OnModelCreating:**
    - Event entity: add `DjUserId` index
    - Request entity: add `UserId` index, add `(EventId, Status)` composite index
    - Vote entity: add `RequestId` index, add `UserId` index
    - Session entity: add `EventId` index

    Build: `dotnet build src/CrowdQR.API/CrowdQR.Api.csproj`
