  <name>Task 1: Install and configure MiniProfiler in the API project</name>
  <files>
    src/CrowdQR.API/CrowdQR.Api.csproj
    src/CrowdQR.API/Program.cs
  </files>
  <action>
    1. Add MiniProfiler NuGet package to CrowdQR.Api.csproj:
       ```
       dotnet add src/CrowdQR.API/CrowdQR.Api.csproj package MiniProfiler.AspNetCore.Mvc
       ```
       This package includes EF Core integration via the `.AddEntityFramework()` extension.

    2. In Program.cs, register MiniProfiler services (add AFTER `builder.Services.AddControllers()` and BEFORE `var app = builder.Build()`):
       ```csharp
       // MiniProfiler for development query profiling
       if (builder.Environment.IsDevelopment())
       {
           builder.Services.AddMiniProfiler(options =>
           {
               options.RouteBasePath = "/profiler";
               // Only authorize in development
               options.ResultsAuthorize = _ => true;
               options.ResultsListAuthorize = _ => true;
               // Track unviewed sessions for 30 minutes
               options.TrackConnectionOpenClose = true;
           }).AddEntityFramework(); // EF Core query tracking
       }
       ```

    3. In Program.cs, add MiniProfiler middleware (MUST come BEFORE UseEndpoints/MapControllers):
       After `app.UseAuthorization();` and before `app.MapHub<CrowdQRHub>(...)`:
       ```csharp
       if (app.Environment.IsDevelopment())
       {
           app.UseMiniProfiler();
       }
       ```
       IMPORTANT: `UseMiniProfiler()` must be called before `MapControllers()` and `MapHub()` to profile those requests.

    4. Verify MiniProfiler doesn't conflict with existing middleware order:
       Current order: UseExceptionHandling -> UseCors -> UseRouting -> UseAuthentication -> UseAuthorization -> custom middlewares
       MiniProfiler should go after UseAuthorization and before MapHub/MapControllers.

    Build: `dotnet build src/CrowdQR.API/CrowdQR.Api.csproj`
  </action>

    - grep for "AddEntityFramework" in Program.cs confirms EF Core integration

       ```html

       {
           <mini-profiler />
       }
       ```
       NOTE: MiniProfiler's tag helper requires the `MiniProfiler.AspNetCore.Mvc` package to be referenced by the Web project, OR the API needs to serve the profiler assets. Since the Web project calls the API via HTTP (not directly), the MiniProfiler widget in the Web layout will show Web-side request timings.

       ALTERNATIVE: If the Web project doesn't reference MiniProfiler directly, instead add a script tag pointing to the API's MiniProfiler includes endpoint:
       ```html
       @if (Environment.GetEnvironmentVariable("ASPNETCORE_ENVIRONMENT") == "Development")
       {
           <script async src="/profiler/includes.min.js?v=4.3.8"
                   data-version="4.3.8"
                   data-path="/profiler/"
                   data-scheme="auto"
                   data-authorized="true"
                   data-position="Left"
                   data-trivial="true"
                   data-children="false"
                   data-max-traces="15"
                   data-toggle-shortcut="Alt+P"></script>
       }
       ```

       The simpler approach: Add MiniProfiler package to the Web project too, and register it the same way. Since the Web project already has its own Program.cs, add:
